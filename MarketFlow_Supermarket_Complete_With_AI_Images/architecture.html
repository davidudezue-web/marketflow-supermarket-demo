CLOUD ARCHITECTURE

Recommended production layers

01

Frontend: GitHub Pages / static hosting

Public shopping pages, product browsing, account screens, order forms and responsive design.

02

Backend API + transactional database

Supabase/PostgreSQL or another managed backend. Validate prices and stock server-side, store transactions and enforce access policies.

03

Authentication and operational permissions

Separate customer access from cashier, manager and administrator access. Never publish database service-role secrets in static HTML.

04

Payment and fulfilment integrations

Use a verified payment provider and webhook confirmation, then reserve stock, notify staff and track fulfilment. Demo checkout does none of this.

05

Analytics and reporting

Validated sales, order lines, returns and stock events flow to Power BI or reporting warehouse for scheduled management reports.

OPERATING CONTROLS

What must be production-grade?

Secure checkout

Server-calculated totals, rate limiting, checkout validation and proper order confirmations.

Inventory consistency

Atomic deductions and stock reservations prevent overselling when multiple customers buy simultaneously.

Privacy by design

Collect only necessary customer data, publish a privacy notice and enforce role-based data access.

Reliable operations

Payment reconciliation, order lifecycle, return handling, backups, alerts and incident procedures.

Trustworthy AI analysis

Check source completeness, transaction keys, waste definitions, aggregate reconciliations and model limitations.

Governance

Real business owner, test plan, acceptance criteria, ongoing support and data retention policy.
